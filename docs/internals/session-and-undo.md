# 세션과 되돌리기

**이 문서를 읽으면** `Load`가 실제로 무엇을 바꾸는지, 되돌리기가 왜 스트로크 단위로 딱 떨어지는지, 트랜잭션이 무엇이고 왜 `Bake`를 막는지, 그리고 스크립트 컴파일에서 작업이 살아남는 이유를 알 수 있습니다.

## Work Mesh {#work-mesh}

`Load`를 누르면 도구는 원본 메쉬를 **복제**해 임시 메쉬를 만들고, 렌더러의 메쉬 참조를 그 사본으로 바꿉니다. 이 사본이 Work Mesh입니다.

- 원본 에셋 파일은 열지도 쓰지도 않습니다.
- 모든 편집 — 브러시, 기즈모, 웨이트, 블렌드쉐이프 구조 변경 — 은 Work Mesh 위에서 일어납니다.
- 세션이 끝나면(`Revert`, 창 닫기, 플레이모드 진입) 렌더러는 원본 참조로 되돌아가고 Work Mesh는 버려집니다.

`Bake`만이 이 사본을 파일로 내보냅니다. → [Bake 내부](/internals/bake)

## 웰드 그룹 {#웰드-그룹}

Unity 메쉬는 UV 심, 노멀 심, 재질 경계에서 **같은 위치의 정점을 여러 개로 쪼개** 둡니다. 화면에서는 점 하나로 보이지만 데이터에는 서너 개가 있습니다.

도구는 로컬 공간 위치가 같은 정점들을 하나의 **웰드 그룹**으로 묶어 다룹니다.

- 선택은 그룹 전체를 함께 잡습니다.
- 브러시와 기즈모 변형은 그룹 전체에 같은 값을 씁니다.
- 웨이트 페인트 결과도 그룹 전체에 동일하게 기록됩니다.

이 때문에 "정점 하나만 옮겼는데 UV 심이 안 벌어진다" 가 성립합니다.

대칭도 같은 개념 위에 있습니다. 좌우 대응은 인덱스가 아니라 로컬 공간 기본 위치의 그룹 매칭으로 찾습니다 — 그래서 좌우 정점 수가 정확히 같지 않아도 동작합니다.

## 되돌리기 {#되돌리기}

Unity의 `Ctrl+Z` 를 그대로 씁니다. 도구는 자체 되돌리기 스택을 두지 않고 Unity의 것에 얹습니다.

**의도 하나 = 되돌리기 한 단계** 가 규칙입니다.

| 작업 | 되돌리기 단위 |
|---|---|
| 브러시 스트로크 | 마우스를 누르고 뗄 때까지 전체가 한 단계 |
| 기즈모 변형 | 한 번의 드래그가 한 단계 |
| `G`/`R`/`S` 모달 | 확정 한 번이 한 단계 |
| 웨이트 브러시 | 스트로크 하나가 한 단계 |
| `선택 본 스무딩` 슬라이더 | 손을 뗄 때 한 단계로 확정 |
| 삭제·분리·병합·키 구조 변경 | 작업 하나가 한 단계 |
| 다중 메쉬 일괄 작업 | 전체가 하나의 복합 단계 |

마스크 변경도 되돌리기 대상입니다. 반대로 **숨기기는 아닙니다** — 메쉬 데이터가 아니라 세션의 표시 상태이기 때문입니다(블렌더와 같은 규칙).

### 구조 스냅샷

정점 수나 인덱스가 바뀌는 작업(삭제, 분리, 병합, 키 추가·삭제)은 값 하나를 되돌리는 것으로 복구할 수 없습니다. 이런 작업은 **작업 전 메쉬 전체를 스냅샷**으로 떠 두고, 되돌리기가 오면 그것을 복원합니다.

스냅샷에 담기는 것: 정점·노멀·탄젠트·UV0~UV7·컬러·삼각형과 서브메쉬 토폴로지·bindpose·본 웨이트(가변 포함)·블렌드쉐이프 전 프레임.

스냅샷은 메모리를 먹으므로 상한이 있습니다. 넘으면 오래된 것부터 버리고 알려 줍니다 — `구조 언두 기록이 메모리 한도를 넘어 오래된 기록 {0}개를 버렸습니다.`

## 트랜잭션 {#트랜잭션}

블렌드쉐이프의 **새 키 조형**과 **기존 키 편집**은 여러 단계에 걸친 작업이고, 중간 상태를 그대로 저장하면 안 됩니다. 그래서 시작과 끝이 명시적인 트랜잭션으로 감쌉니다.

- 시작하면 창 배지가 `트랜잭션 중` 이 되고 씬뷰에 고정 바가 뜹니다.
- `Enter` = 확정, `Esc` = 취소. 창에 포커스가 있어도 같은 키가 동작합니다.
- 트랜잭션이 열려 있는 동안 `새 쉐이프로 저장`과 `Bake` 는 둘 다 막힙니다.

트랜잭션 중에도 `스컬프트`·`편집` 탭으로 옮겨 작업할 수 있습니다. 다만 정점 수가 바뀌는 작업은 키로 저장할 수 없습니다 — `정점 수가 달라져 블렌드쉐이프로 저장할 수 없습니다. 구조 변경을 되돌린 뒤 다시 시도하세요.`

### 되돌리기가 트랜잭션을 무효로 만들 때

`Ctrl+Z`가 트랜잭션 시작 시점보다 앞으로 가면 편집의 기준이 사라집니다. 이때 도구는 조용히 진행하지 않고 편집을 취소합니다.

> `실행취소가 '{0}' 편집 시작 이전까지 되돌아가 편집 내용이 무효화되었습니다. 안전을 위해 편집을 취소했습니다.`

다시 실행 쪽도 같습니다. 판정은 관측이 아니라 트랜잭션 시작 시점에 기록해 둔 값으로 하므로 결정적입니다.

## 자동 저장과 복원 {#자동-저장과-복원}

Unity는 스크립트를 저장할 때마다 도메인을 다시 로드합니다. 그때 에디터 창의 상태는 대부분 초기화됩니다. 편집 세션을 그냥 두면 저장하지 않은 작업이 경고 없이 사라집니다.

그래서 리로드 직전에 이렇게 합니다.

1. 진행 중인 트랜잭션을 조용히 확정합니다 (모달 대화상자를 띄우지 않습니다 — 리로드 중에는 띄울 수 없습니다). 확정이 안 되면 취소합니다.
2. Work Mesh를 `Library/EmeAutoSave/<렌더러 ID>.asset` 으로 직렬화합니다.
3. 리로드가 끝나면 자동으로 다시 불러와 세션을 복원합니다 — `Easy Mesh Editor: 자동 저장된 편집 세션을 복원했습니다 ({0})`

알려진 한계:

- dirty 판정이 없습니다. `Load`만 하고 아무것도 안 했어도 저장·복원합니다.
- 창을 두 개 열어 두었다면 하나만 복원됩니다.
- 에디터 크래시는 대상이 아닙니다.

창을 닫거나 플레이모드에 들어갈 때는 자동 저장이 아니라 물어봅니다 — `Bake` / `버리기` (플레이모드는 `취소`까지). → [생성되는 파일](/reference/output-files#자동-저장-폴더)

## 세션이 끝나는 방법

| 방법 | 결과 |
|---|---|
| `Bake` | 에셋으로 저장하고 종료 |
| `Revert` | 원본으로 되돌리고 종료 |
| 창 닫기 | 물어본 뒤 종료 |
| 플레이모드 진입 | 물어본 뒤 종료 |
| 다른 대상으로 전환 | `'{0}'의 편집 내용이 아직 저장되지 않았습니다. … 편집을 버리고 대상을 전환할까요?` |

`Tab`은 여기에 없습니다. 편집 입력만 끄고 세션은 살아 있습니다.

세션 도중에 렌더러나 메쉬가 씬에서 사라지면 그 세션만 조용히 정리되고 나머지는 유지됩니다.
