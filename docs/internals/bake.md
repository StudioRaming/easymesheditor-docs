# Bake 내부

**이 문서를 읽으면** `Bake`가 어떤 순서로 무엇을 하는지, 언제 정점을 정리하고 언제 건너뛰는지, 그리고 5개 이상 본 영향을 가진 메쉬가 어떻게 보존되는지 알 수 있습니다.

## 순서

1. 트랜잭션이 열려 있으면 중단합니다.
2. 자동 정규화가 꺼진 채 작업했다면 웨이트를 한 번 정규화합니다.
3. Work Mesh의 사본을 만듭니다 (라이브 메쉬는 건드리지 않습니다).
4. 사본에서 [고아 정점을 정리](#고아-정점-정리)합니다.
5. 데이터를 검증합니다 — NaN/Infinity, 토폴로지, 배열 길이.
6. `provenance` 로 출력 경로를 정하고 에셋을 씁니다.
7. 렌더러가 새 에셋을 쓰게 하고 세션을 끝냅니다.

메쉬가 크면 진행률 바가 뜹니다 — `메쉬 굽는 중` · `사용되지 않는 정점 정리 중...` · `메쉬 에셋 저장 중...`

## 고아 정점 정리 {#고아-정점-정리}

`선택 삭제 (X · {0} 페이스)` 는 삼각형만 지우고 정점 버퍼는 그대로 둡니다. 라이브 Work Mesh의 인덱스가 선택·마스크·되돌리기 스냅샷과 묶여 있어서, 편집 도중에 정점을 재배치하면 그 전부가 어긋나기 때문입니다.

그래서 정리는 **`Bake` 할 때 사본에서 딱 한 번** 합니다. 어떤 서브메쉬 삼각형도 참조하지 않는 정점을 제거하고 나머지를 리매핑합니다.

결과는 `사용되지 않는 정점 {0}개를 정리했습니다` 로 보고됩니다.

보존되는 것: 노멀·탄젠트·UV0~UV7·컬러·본 웨이트(가변 영향 포함)·bindpose·블렌드쉐이프 전 프레임.

정리는 staging 사본에서 전 과정을 수행하고 완전히 성공했을 때만 대상에 복사합니다. 절반만 재작성된 메쉬는 남지 않습니다.

### 건너뛰는 경우

| 조건 | 메시지 |
|---|---|
| 삼각형이 아닌 서브메쉬(Quad/Line/Point)가 있음 | `삼각형이 아닌 서브메쉬(Quad/Line/Point)가 있어 고아 정점 정리를 건너뜁니다.` |
| 이름이 같은 블렌드쉐이프가 있음 | `이름이 같은 블렌드쉐이프가 있어 고아 정점 정리를 건너뜁니다.` |
| 정리 자체가 실패 | `고아 정점 정리에 실패해 메쉬를 그대로 두었습니다.` |

건너뛰어도 `Bake` 는 진행됩니다. 정점이 줄지 않을 뿐입니다.

## 노멀

`Bake`는 노멀을 임의로 다시 계산하지 않습니다. 편집 중에 명시적으로 만든 것만 반영됩니다.

- `노멀 재계산` — 선택 정점의 노멀을 면적 가중 스무스로 다시 계산합니다.
- `노멀 뒤집기` — 선택 페이스의 winding을 반전하고, 블렌드쉐이프의 노멀·탄젠트 델타와 정점 탄젠트도 함께 반전합니다.
- 블렌드쉐이프 키를 만들거나 고칠 때는 그 키의 노멀 델타가 면적 가중으로 다시 계산됩니다. 기존 키 저장, 새 키 저장, `새 쉐이프로 저장` 세 경로 모두 같습니다.

## 가변 본 웨이트 {#가변-본-웨이트}

Unity 2020.1부터 메쉬는 정점당 4개를 넘는 본 영향을 가질 수 있습니다. 레거시 `BoneWeight` API는 4개까지만 다루므로, 그것만 쓰면 **편집하지 않은 정점까지 메쉬 전체가 4슬롯으로 잘립니다.**

그래서 세션은 `Load` 시점에 원본의 가변 웨이트 데이터를 따로 보관합니다.

- 웨이트를 칠하면 **건드린 웰드 그룹만** 4슬롯으로 교체하고,
- 나머지는 보관해 둔 원본 그대로 두고,
- 저장할 때 둘을 합쳐 한 번에 다시 씁니다.

결과적으로 팔 하나에 웨이트를 칠해도 다리의 5영향 정점은 그대로 남습니다.

되돌리기 스냅샷, 삭제·분리, 최종 동기화까지 모두 이 경로를 지납니다. Unity 2019.4에서는 애초에 가변 웨이트가 없으므로 레거시 4슬롯 그대로입니다.

:::caution[분리된 파트는 예외입니다]
`선택 분리 (P)` 로 떼어낸 `_Part.asset` 은 4슬롯으로 제한됩니다. → [제한 사항](/limitations)
:::

## 이름 맞추기

Unity는 에셋 파일 안의 메인 오브젝트 이름이 파일 이름과 다르면 경고를 냅니다. `Bake`는 저장 직전에 메쉬 오브젝트의 이름을 파일 이름과 같게 맞춥니다.

## 실패했을 때

`Bake`가 실패하면 **세션이 닫히지 않습니다.**

> `Bake 실패 (성공 {0} / 실패 {1}): {2} — 실패한 세션은 유지되어 다시 시도할 수 있습니다.`

여러 메쉬를 함께 구웠다면 성공한 것만 에셋으로 나가고, 실패한 세션은 열린 채로 남아 다시 시도할 수 있습니다. 결과는 `Bake 결과 ({0}/{1} 성공)` 표로 정리됩니다. → [창 사용법](/guides/window)

## 컬러 버퍼

메쉬의 컬러 채널이 8비트(UNorm8)로 임포트되어 있으면 float 컬러를 그대로 쓸 수 없습니다. 스냅샷·정리·분리·세션 동기화 모두 하나의 읽기/쓰기 경로를 지나며, 원본 메쉬의 포맷을 그대로 따라 씁니다.
