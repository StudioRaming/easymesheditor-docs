# 블렌드쉐이프

**이 문서를 읽으면** 표정 키 목록을 다루는 법, 새 키를 조형하는 법과 기존 키를 다시 손보는 트랜잭션, 미러 키·전송·합치기 같은 관리 기능, 그리고 `새 쉐이프로 저장`과 `Bake`의 차이를 알 수 있습니다.

:::note[`SkinnedMeshRenderer` 전용입니다]
일반 `MeshRenderer` 대상에서는 `블렌드쉐이프는 SkinnedMeshRenderer 전용입니다. 일반 MeshRenderer 대상에서는 사용할 수 없습니다.` 가 대신 표시됩니다.
:::

## 목록 {#목록}

머리글은 `블렌드쉐이프 {0}개` 입니다. 각 행에 이름, 값 슬라이더, 숫자 입력이 있습니다.

- 값은 `0~100` 이며 실시간으로 미리보기에 반영됩니다.
- 이름이나 값을 좌우로 드래그해도 값이 바뀝니다. `Shift`를 함께 누르면 미세 조절입니다.
- `전체 값 0으로` 로 한 번에 초기화합니다.

목록 위의 검색 상자로 이름을 걸러냅니다. `×` 로 검색을 지웁니다.

표시할 키가 없으면 `표시할 블렌드쉐이프가 없습니다. '+ 새 쉐이프'로 만들어 보세요.` 가 나옵니다.

### 행의 세 버튼

| 버튼 | 하는 일 |
|---|---|
| `S` | 그 키만 100으로 보는 솔로 프리뷰 (`Esc`로 해제) |
| `L` | 실수 방지 잠금 |
| `M` | 미러 키 생성 |

### 접두사 그룹 {#접두사-그룹}

`그룹` 을 켜면 이름의 접두사로 목록이 접힙니다. `_` 를 우선 구분자로 봅니다 — `eye_blink`, `eye_wide` 는 `eye` 그룹으로 묶입니다. 그룹 머리글은 `{이름} ({개수})` 형태입니다.

### 확장 범위 {#확장-범위}

`확장 범위` 를 켜면 슬라이더가 `-100~200` 까지 열립니다. 외삽이므로 형태가 깨질 수 있습니다 — 확인용으로 쓰고 그대로 저장하지 마세요.

### 델타 히트맵 {#델타-히트맵}

`히트맵` 을 켜고 목록에서 키 이름을 클릭하면, 그 키가 실제로 움직이는 정점이 색으로 표시됩니다. 상태는 `히트맵: '{0}' · 최대 이동량 {1}` 로 나옵니다.

키를 고르지 않았다면 `히트맵을 보려면 목록에서 키 이름을 클릭해 선택하세요.` 가 표시됩니다.

### 솔로 프리뷰 {#솔로-프리뷰}

행의 `S` 를 누르면 그 키만 100으로 켠 상태를 봅니다. 다른 키의 값은 화면에서만 잠시 물러납니다. `Esc` 로 해제합니다.

솔로 중에는 여러 키의 값을 한꺼번에 바꿀 수 없습니다 — `솔로 프리뷰 중에는 weight 를 일괄 변경할 수 없습니다. 먼저 솔로(핀)를 해제하세요.`

### 잠금 {#잠금}

행의 `L` 로 그 키를 잠급니다. 잠긴 키를 건드리려 하면 `'{0}' 키는 잠겨 있습니다. 행의 'L' 을 다시 눌러 잠금을 풀어야 바꿀 수 있습니다.` 가 나옵니다. 잠금은 일괄 작업과 키 전송에서도 존중됩니다.

## 여러 키를 한 번에 {#다중-선택}

이름을 클릭하면 선택되고, `Ctrl`·`Shift` 클릭으로 여러 개를 고릅니다. `Shift` 범위 선택은 화면에 보이는 행 기준입니다. 선택 개수는 `선택 {0}개` 로 표시됩니다.

| 버튼 | 하는 일 |
|---|---|
| `값 적용` | 고른 키 전부에 같은 값을 넣습니다 |
| `0으로` | 고른 키를 0으로 |
| `잠금` / `해제` | 고른 키를 잠그거나 풉니다 |
| `^` / `v` | 순서를 위/아래로 옮깁니다 |
| `삭제` | 고른 키를 지웁니다 |
| `선택 해제` | 선택만 풉니다 |

삭제는 `선택한 키 {0}개를 삭제할까요? Ctrl+Z 한 번으로 전부 되돌릴 수 있습니다.` 로 확인합니다. 일괄 구조 변경은 하나의 되돌리기 단계입니다.

고른 키가 전부 잠겨 있으면 `선택한 키가 모두 잠겨 있어 아무것도 바꾸지 않았습니다.` 로 끝납니다. 중간에 실패하면 `일괄 작업에 실패해 모든 메쉬를 작업 전 상태로 되돌렸습니다.` 로 전부 롤백합니다.

## 새 쉐이프 조형 {#새-쉐이프-조형}

`+ 새 쉐이프 (N)` 또는 씬뷰에서 `N`.

지금의 절대 형태를 기준으로 조형이 시작되고, 씬뷰 위에 `새 쉐이프 조형 중: {0}` 배너가 뜹니다.

- 드래그 = 그랩, `Shift` = 스무딩
- `F` = 반경, `Shift+F` = 강도
- `Enter` = `새 키 변경 확정 (Enter)`, `Esc` = `취소 (Esc)`

이름은 `이름` 필드에서 정합니다. 쓸 수 없는 문자가 있으면 `이름에 사용할 수 없는 문자(/ \ 줄바꿈 탭)를 '_'로 바꿔 '{0}'(으)로 저장했습니다.` 와 함께 정리됩니다.

## 기존 키 편집 {#기존-키-편집}

행의 편집 버튼을 누르면 그 키의 **마지막 프레임 100% 형태**를 단독 미리보기로 불러오고, 편집 트랜잭션이 시작됩니다. 창 배지가 `트랜잭션 중` 이 되고 씬뷰에 `편집 중인 쉐이프: {0}` 바가 고정됩니다.

트랜잭션 중에도 `스컬프트`·`편집` 탭으로 이동해 작업할 수 있습니다 (`멀티탭 편집`). 창은 이렇게 안내합니다 — `스컬프트 또는 편집 탭으로 이동해 수정한 뒤 여기로 돌아와 저장하세요. 정점 삭제·분리처럼 정점 수가 바뀌는 작업은 저장할 수 없습니다.`

끝낼 때는 고정 바에서 둘 중 하나를 고릅니다.

- `현재 키 변경 확정 (Enter)` — 세션에 확정합니다.
- `취소 (Esc)` — 버립니다.

:::caution[여기서 확정해도 아직 에셋은 안 바뀝니다]
창의 문구 그대로 — `여기서는 쉐이프 변경을 작업 세션에 확정합니다. 모든 작업을 마친 뒤 상단 Bake를 눌러야 메쉬 에셋에 최종 저장됩니다.`
:::

확정하지 않은 채로 저장을 누르면 `'{0}' 쉐이프가 아직 편집 중입니다. 현재 키 변경을 확정하거나 취소한 뒤 최종 저장하세요.` 와 함께 블렌드쉐이프 탭으로 되돌아갑니다.

### 프레임이 여러 개인 키 {#다중-프레임}

프레임이 둘 이상인 키를 편집하면 경고가 뜹니다 — `이 키는 프레임 {0}개입니다. 마지막 프레임(100%)만 편집됩니다`

저장하면 `중간 프레임 {0}개는 마지막 프레임의 변화량에 비례해 함께 갱신되었습니다.` 로 보고됩니다. 중간 프레임을 개별로 손보는 기능은 없습니다. → [제한 사항](/limitations)

### 되돌리기가 편집 시작 이전으로 갔을 때

`Ctrl+Z`가 편집을 시작한 시점보다 앞으로 가 버리면 트랜잭션이 성립하지 않습니다. 이때 도구는 편집을 자동으로 취소하고 알려 줍니다 — `실행취소가 '{0}' 편집 시작 이전까지 되돌아가 편집 내용이 무효화되었습니다. 안전을 위해 편집을 취소했습니다.` 다시 실행 쪽도 같은 규칙입니다.

## 기본형 직접 수정 {#기본형-직접-수정}

키를 고르지 않은 채로 `스컬프트`나 `편집`에서 메쉬를 바꾸면 그것은 기본형 수정입니다. 블렌드쉐이프 탭이 `기본형 직접 수정 감지 — 신규 키로 저장하세요` 로 알려 주고 두 버튼을 줍니다.

- `신규 키로 확정` — 그 변형을 새 키로 만듭니다.
- `기본형 수정 되돌리기` — `키를 선택하지 않고 수정한 내용을 모두 되돌릴까요?`

이 상태로 `Bake`를 누르면 창이 `기본형에 굽기` 와 신규 키 확정 중 어느 쪽인지 물어봅니다.

## 관리 {#관리}

| 버튼 | 하는 일 |
|---|---|
| `이름` | 이름을 바꿉니다 |
| `복제` | 같은 내용의 키를 하나 더 만듭니다 (`_Copy`) |
| `리버트` | 반전 키를 만듭니다 (`_Revert`). 기본형이 바뀐 아바타에서 원래 표정을 되찾을 때 씁니다 |
| `삭제` | `'{0}' 쉐이프를 삭제할까요? Ctrl+Z로 되돌릴 수 있습니다.` |
| `^` / `v` | 순서를 옮깁니다 |

이름이 같은 키가 여러 개 있으면 `이 메쉬에 같은 이름의 키가 여러 개 있습니다 (예: '{0}'). 목록에서 클릭한 항목만 편집됩니다.` 로 알려 줍니다.

### 적용값 합치기 {#적용값-합치기}

`적용값 합치기` 는 지금 0이 아닌 키들의 **보이는 결과**를 하나의 새 100% 키로 합치고, 재료로 쓴 원래 키들의 값을 0으로 되돌립니다. 프레임이 여러 개인 키의 보간·외삽까지 계산합니다.

### 미러 키 {#미러-키}

행의 `M` 또는 `미러 축` 을 정하고 실행합니다. 결과는 `미러 키 '{0}' 을(를) {1}축 기준으로 만들었습니다.` 입니다.

이름은 원본 이름의 좌우 표기를 뒤집어 정합니다. 규칙은 순서대로:

| 원본 이름 | 미러 이름 |
|---|---|
| `...Left...` | `...Right...` (대소문자 무시 매칭도 시도) |
| `xxx_L` | `xxx_R` |
| `L_xxx` | `R_xxx` |
| `xxx.L` | `xxx.R` |
| 좌우 표기가 없음 | `xxx_Mirror` |

정점 짝 찾기는 `스컬프트`·`편집`의 대칭과 같은 공간 매칭을 씁니다. 짝이 없는 정점은 대칭 평면 위에 있을 때만 반사되고, 아니면 움직이지 않습니다. 노멀 델타도 같은 반사를 받고, 프레임이 여러 개면 모든 프레임을 미러합니다.

짝을 찾지 못하면 `'{0}' 의 미러 키를 만들지 못했습니다. 대칭 짝을 찾지 못했거나 메쉬가 유효하지 않습니다.` 로 끝납니다.

### 다른 메쉬에서 키 가져오기 {#키-전송}

`다른 메쉬에서 키 가져오기` 섹션입니다. 아바타 얼굴의 표정 키를 새로 만든 헤어나 소품으로 옮길 때 씁니다.

1. `소스 메쉬` 를 지정합니다 — `소스 메쉬를 지정하면 그 메쉬의 키 목록이 나타납니다.`
2. 가져올 키를 체크합니다. `전체 선택` / `전체 해제` 가 있습니다.
3. `최대 거리` 를 정합니다. 이 거리 안에서 대응점을 찾습니다.
4. `가져오기` 를 누릅니다.

결과는 `키 {0}개를 가져왔습니다. 대응점을 찾지 못한 정점 {1}개는 움직이지 않습니다 — 최대 거리를 늘려 보세요.` 로 나옵니다.

| 상황 | 메시지 |
|---|---|
| 편집 중인 메쉬를 소스로 지정 | `지금 편집 중인 메쉬는 소스로 쓸 수 없습니다. 다른 메쉬를 지정하세요.` |
| 소스가 Read/Write 꺼짐 | `소스 메쉬의 Read/Write 가 꺼져 있어 정점을 읽을 수 없습니다.` |
| 소스에 키가 없음 | `이 소스 메쉬에는 블렌드쉐이프가 없습니다.` |
| 같은 이름이 이미 있음 | `같은 이름의 키 {0}개가 이미 있습니다. 가져온 내용으로 교체할까요?` |
| 잠긴 키가 섞임 | `잠긴 키 {0}개는 건너뛰었습니다.` |

실패하면 `키 가져오기에 실패해 모든 메쉬를 작업 전 상태로 되돌렸습니다.` 로 전부 롤백합니다.

## 빠른 캡처와 Bake {#빠른-캡처와-bake}

둘 다 저장이지만 하는 일이 다릅니다.

| | `새 쉐이프로 저장` | `Bake` |
|---|---|---|
| 저장 대상 | 기본형에 **이번에 더한 변형만** 새 키로 | Work Mesh **전체** (정점·웨이트·키 구조) |
| 에셋 | 아직 안 바뀜 | `<원본명>_Edit.asset` 생성 |
| 세션 | 계속 | 끝남 |
| 기본형 | 유지 | 지금 상태 그대로 |

`새 쉐이프로 저장`은 블렌드쉐이프 값으로 재생 중인 모양을 섞지 않습니다. 저장한 키는 100으로 켜져 현재 모습이 유지되고, 다음 캡처 기준이 갱신되어 이전 변형이 두 번 저장되지 않습니다.

창의 안내 그대로 — `기본형은 유지됩니다. 새 키는 100으로 켜져 현재 모습이 유지되며, 다음 캡처에는 이번 키가 포함되지 않습니다.`

캡처할 변형이 없으면 `새 키로 캡처할 추가 기본형 변형이 없습니다.` 가 나옵니다.

## 여러 메쉬에서 {#다중-메쉬-키}

모든 대상이 `SkinnedMeshRenderer` 여야 합니다 — 아니면 `여러 메쉬의 블렌드쉐이프를 함께 편집하려면 선택한 대상이 모두 SkinnedMeshRenderer여야 합니다.`

목록에는 **모든 대상에 이름이 같은 키만** 나옵니다 (`공통 블렌드쉐이프 {0}개 · 메쉬 {1}개`). 인덱스는 서로 달라도 됩니다. 값·편집·관리는 모든 메쉬에 동시에 적용됩니다.

공통 키가 하나도 없으면 `모든 선택 메쉬에 공통으로 존재하는 블렌드쉐이프가 없습니다. 새 쉐이프는 같은 이름으로 모두 추가됩니다.` 가 표시됩니다. → [다중 메쉬](/guides/multi-mesh)
