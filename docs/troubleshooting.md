# 문제 해결

증상으로 찾으세요. 대부분은 **세션이 아직 열리지 않았거나, 탭이 대상과 맞지 않거나, 표정 키 편집이 열려 있다** 셋 중 하나입니다.

## 창은 열리는데 아무것도 못 한다

| 확인 | 조치 |
|---|---|
| 대상이 없다는 안내 | Hierarchy에서 메쉬 렌더러가 있는 오브젝트를 고르세요 |
| 대상은 골랐는데 편집이 시작되지 않음 | `불러오기`를 아직 누르지 않았습니다 |
| 편집 입력이 꺼져 있다는 안내 | `Tab` 또는 씬뷰의 편집 시작 |
| 탭 본문 대신 안내문만 보임 | 그 탭이 `SkinnedMeshRenderer` 전용입니다 |

## `불러오기`가 안 된다

| 원인 | 조치 |
|---|---|
| 메쉬 렌더러가 없음 | 자식까지 포함해 렌더러가 있는지 확인하세요 |
| Read/Write가 꺼져 있음 | 상태줄의 `Read/Write 켜기` 버튼을 누른 뒤 `불러오기`를 다시 누르세요 |
| 같은 원본을 쓰는 렌더러 | 이제 각각 따로 불러와 따로 편집합니다. 필요 없는 쪽은 후보 목록에서 빼세요 |
| 원본 메쉬가 `Assets` 폴더 밖에 있음 | Unity 기본 제공 메쉬와 패키지 메쉬는 읽기 전용이라 `메쉬 저장`으로 저장할 수 없습니다. 메쉬를 `Assets` 폴더로 복사해 렌더러에 연결한 뒤 다시 불러오세요 |

## `표정 키`와 `뼈 연결` 탭이 비활성이다

두 탭은 `SkinnedMeshRenderer` 전용입니다. 여러 메쉬를 함께 열었다면 **전부** SMR이어야 표정 키를 함께 편집할 수 있습니다.

## `메쉬 저장` 버튼이 눌리지 않는다

배지가 `키 편집 중`인지 보세요. 표정 키 편집이 확정되지 않으면 `메쉬 저장`과 `새 키로 저장`이 모두 막힙니다. 창 상단의 고정 바에서 `저장`(확정) 또는 `키 편집 취소`를 먼저 누르세요. → [표정 키](/guides/blendshape#기존-키-편집)

## 씬뷰에 아무것도 안 그려진다

| 원인 | 조치 |
|---|---|
| **셰이더 두 개가 빠졌다** | `Editor/Shaders/EmeOverlay.shader`와 `EmeSceneGL.shader`를 함께 설치하세요. → [설치](/getting-started/installation) |
| 편집 입력이 꺼져 있다 | `Tab` |
| 가려진 요소를 보려 한다 | `Alt+Z`로 X-Ray를 켜세요 |

## `Alt+클릭`이 엣지 루프 대신 카메라를 돌린다

의도된 동작입니다. 루프 선택은 **움직이지 않은 클릭**에서만 일어납니다. 마우스를 누른 자리에서 거의 움직이지 않고 떼세요. → [선택·이동](/guides/edit#엣지-루프와-엣지-링)

## `R`이 회전이 아니라 스케일 기즈모가 된다

`R`은 선택이 있고 커서가 씬뷰 위에 있을 때만 회전 모달입니다. 선택이 비어 있거나 커서가 창 쪽에 있으면 Unity식 `R` 스케일 기즈모로 동작합니다.

## 씬뷰에서 `X` `Y` `Z`를 눌러도 대칭이 안 켜진다

축 대칭 단축키는 `Alt+Shift+X` / `Y` / `Z`입니다. 단독 키는 Unity의 툴 핸들 단축키로 남겨 두었습니다. 창의 `대칭` 체크박스로도 켤 수 있습니다. → [단축키](/reference/shortcuts)

## 대칭이 반대편에 안 먹는다

| 원인 | 조치 |
|---|---|
| 축을 잘못 골랐다 | `평면 표시`를 켜고 평면 위치를 확인하세요 |
| 애초에 좌우 대칭이 아닌 메쉬 | 짝을 찾지 못한 정점은 대칭 처리에서 빠집니다 |

## 본을 칠해도 아무 일도 안 일어난다

| 원인 | 조치 |
|---|---|
| 활성 본이 없음 | 본 목록의 라디오로 칠할 본을 고르세요 |
| 본이 잠김 | 행의 `L`을 해제하세요 |
| 슬롯이 꽉 참 | 다른 본의 웨이트를 먼저 빼거나 `최대 영향 본 수`를 확인하세요 |

## 웨이트 가져오기 결과가 통째로 어긋난다

소스와 대상의 트랜스폼이 다른 경우입니다. 창이 경고하면 `소스 트랜스폼 무시 (바인드포즈 로컬 공간 매칭)`를 켜고 다시 실행하세요. → [뼈 연결](/guides/weight-paint#전송-공간)

일부 정점만 어긋난다면 `최대 거리`를 조금 올려 보세요. 범위 밖 정점 수가 줄어듭니다.

## 표정 키를 편집했는데 다른 프레임이 이상해졌다

프레임이 여러 개인 키는 마지막 프레임(100%)만 편집되고, 중간 프레임은 그 변화량에 **비례해** 갱신됩니다. 중간 프레임을 따로 다루는 기능은 없습니다. → [현재 제한](/limitations)

## 삭제했는데 폴리곤 수가 안 줄었다

정점 정리는 `메쉬 저장`할 때 한 번 일어납니다. 편집 중에는 라이브 메쉬의 인덱스를 바꾸지 않기 때문입니다. 저장 후에도 줄지 않았다면 정리가 건너뛰어진 것입니다. 콘솔에서 건너뛴 이유를 찾아보세요. → [사용되지 않는 정점 정리](/internals/bake#고아-정점-정리)

## `거리로 병합`이 아무것도 합치지 않는다

위치가 같아도 **UV가 다른** 정점은 합치지 않습니다. UV 심을 지키기 위한 규칙입니다. 블렌드쉐이프 델타가 크게 다른 정점도 같은 이유로 빠집니다. → [선택·이동](/guides/edit#거리로-병합)

## 스크립트를 저장했더니 창이 초기화됐다

편집 세션은 자동으로 복원됩니다. 콘솔에서 복원 메시지를 확인하세요. 복원하지 못한 파일은 `Library/EmeAutoSave/`에 그대로 남습니다. 창을 두 개 열어 두었다면 하나만 복원됩니다. → [자동 보존과 복원](/internals/session-and-undo#자동-보존과-복원)

## `메쉬 저장` 했는데 다른 파일이 생겼다

같은 원본을 쓰는 렌더러가 여럿이고 씬이 저장되지 않은 상태였을 수 있습니다. 씬을 저장한 뒤 다시 `메쉬 저장`하세요. → [출처 표식과 owner](/reference/output-files#provenance와-owner)

이름이 같은 다른 에셋이 이미 있었다면, 그것을 덮어쓰지 않으려고 일부러 새 경로를 만든 것입니다.

## `Ctrl+Z`를 눌렀더니 편집이 취소됐다

표정 키 편집 중에 되돌리기가 편집 시작 시점보다 앞으로 간 경우입니다. 기준이 사라져 그대로 진행하면 잘못된 델타가 저장되므로, 편집을 취소합니다. → [세션과 되돌리기](/internals/session-and-undo#되돌리기가-편집을-무효로-만들-때)

## 컴파일 오류가 난다

DLL판과 소스판을 겹쳐 넣었을 가능성이 큽니다. 같은 클래스가 두 번 정의됩니다. 둘 중 하나만 남기세요. → [설치](/getting-started/installation#4-dll판과-소스판을-함께-넣지-마세요)

## 그래도 안 되면
