# 문제 해결

증상으로 찾으세요. 대부분은 **"세션이 안 열렸거나, 대상 탭이 아니거나, 트랜잭션이 열려 있다"** 셋 중 하나입니다.

## 창은 열리는데 아무것도 못 한다

| 확인 | 조치 |
|---|---|
| 대상 행이 `대상 없음 — 오브젝트를 선택하고 Load` | Hierarchy에서 메쉬 렌더러가 있는 오브젝트를 고르세요 |
| `선택: {0}개 렌더러 (Load를 누르세요)` 에서 멈춰 있음 | `Load`를 아직 안 눌렀습니다 |
| `편집이 잠시 꺼져 있습니다.` | `Tab` 또는 `편집 켜기` |
| 탭 본문 대신 안내문만 보임 | 그 탭이 `SkinnedMeshRenderer` 전용입니다 |

## `Load`가 안 된다

| 원인 | 메시지 / 표시 | 조치 |
|---|---|---|
| 메쉬 렌더러가 없음 | `선택한 오브젝트에서 편집 가능한 메쉬 렌더러를 찾을 수 없습니다.` | 자식까지 포함해 렌더러가 있는지 확인 |
| Read/Write 꺼짐 | `메쉬가 Read/Write 비활성 상태입니다.` · 후보 행에 `[Read/Write 꺼짐]` | 창의 `Read/Write 켜기` 버튼 |
| 같은 원본을 공유하는 렌더러 | 후보 행에 `[원본 중복]` | 자동으로 하나만 열립니다 |

## `블렌드쉐이프` / `웨이트` 탭이 비활성이다

두 탭은 `SkinnedMeshRenderer` 전용입니다.

- `블렌드쉐이프는 SkinnedMeshRenderer 전용입니다. 일반 MeshRenderer 대상에서는 사용할 수 없습니다.`
- `웨이트 페인트는 SkinnedMeshRenderer 전용입니다.`

여러 메쉬를 함께 열었다면 **전부** SMR이어야 합니다 — `여러 메쉬의 블렌드쉐이프를 함께 편집하려면 선택한 대상이 모두 SkinnedMeshRenderer여야 합니다.`

## `Bake` 버튼이 눌리지 않는다

배지가 `트랜잭션 중` 인지 보세요. 블렌드쉐이프 편집이 확정되지 않으면 `새 쉐이프로 저장`과 `Bake` 둘 다 막힙니다.

> `'{0}' 쉐이프가 아직 편집 중입니다. 현재 키 변경을 확정하거나 취소한 뒤 최종 저장하세요.`

씬뷰 고정 바에서 `Enter`(확정) 또는 `Esc`(취소)를 먼저 실행하세요. → [블렌드쉐이프](/guides/blendshape#기존-키-편집)

## 씬뷰에 아무것도 안 그려진다

| 원인 | 조치 |
|---|---|
| **셰이더 두 개가 빠졌다** | `Editor/Shaders/EmeOverlay.shader` 와 `EmeSceneGL.shader` 를 함께 설치 → [설치](/getting-started/installation) |
| 편집이 꺼짐 | `Tab` |
| 가려진 요소를 보려 함 | `Alt+Z` 로 X-Ray |

## `Alt+클릭` 이 엣지 루프 대신 카메라를 돌린다

의도된 동작입니다. 루프 선택은 **드래그하지 않은 클릭**에서만 일어납니다. 마우스를 누른 자리에서 거의 움직이지 않고 떼세요. → [편집](/guides/edit#엣지-루프와-엣지-링)

## `R` 이 회전 모달이 아니라 스케일 기즈모가 된다

`R` 은 선택이 있고 커서가 씬뷰 위일 때만 회전 모달입니다. 선택이 비어 있거나 커서가 창 쪽에 있으면 Unity식 `R` = 스케일 기즈모로 동작합니다.

## 씬뷰에서 `X` `Y` `Z` 를 눌러도 대칭이 안 켜진다

`스컬프트`와 `편집` 모두 축 대칭 단축키는 `Shift+Alt+X` / `Y` / `Z` 입니다. 단독 키는 Unity의 툴 핸들 단축키로 남겨 두었습니다. 창의 `대칭` 체크박스로도 켤 수 있습니다. → [단축키](/reference/shortcuts)

## 대칭이 반대편에 안 먹는다

| 원인 | 조치 |
|---|---|
| 축을 잘못 골랐다 | `대칭 평면 표시` 를 켜고 평면 위치를 확인 |
| 비대칭 편집을 한 뒤 | 대칭 맵은 스트로크 시작마다 검사해 갱신됩니다. 한 번 더 시도 |
| 애초에 좌우 대칭이 아닌 메쉬 | 짝을 못 찾은 정점은 그냥 빠집니다 |

## 웨이트를 칠해도 아무 일도 안 일어난다

| 원인 | 메시지 | 조치 |
|---|---|---|
| 활성 본이 없음 | `활성 본이 없습니다 — 목록 왼쪽 라디오를 눌러 칠할 본을 고르세요.` | 라디오로 본 선택 |
| 본이 잠김 | `대상 본이 잠겨 있어 정점 {0}개는 건너뜀` | 행의 `L` 해제 |
| 슬롯이 꽉 참 | `슬롯 4개가 가득 찬 정점 {0}개는 건너뜀 (약한 값)` | 다른 본의 웨이트를 먼저 빼거나 `최대 영향 본 수` 확인 |

## 웨이트 전송 결과가 통째로 어긋난다

소스와 대상의 트랜스폼이 다른 경우입니다. 창이 경고를 띄우면 `소스 트랜스폼 무시 (바인드포즈 로컬 공간 매칭)` 를 켜고 다시 실행하세요. → [웨이트 페인트](/guides/weight-paint#전송-공간)

일부 정점만 어긋난다면 `최대 거리`를 조금 올려 보세요. `범위 밖 {1}정점` 숫자가 줄어듭니다.

## 키를 편집했는데 다른 프레임이 이상해졌다

프레임이 여러 개인 키는 마지막 프레임(100%)만 편집되고, 중간 프레임은 그 변화량에 **비례해** 갱신됩니다.

> `이 키는 프레임 {0}개입니다. 마지막 프레임(100%)만 편집됩니다`

중간 프레임을 개별로 다루는 기능은 없습니다. → [제한 사항](/limitations)

## 삭제했는데 폴리곤 수가 안 줄었다

정점 정리는 `Bake` 할 때 한 번 일어납니다. 편집 중에는 라이브 메쉬의 인덱스를 바꾸지 않기 때문입니다. → [고아 정점 정리](/internals/bake#고아-정점-정리)

`Bake` 후에도 안 줄었다면 건너뛴 것입니다. 콘솔에서 `삼각형이 아닌 서브메쉬…` 또는 `이름이 같은 블렌드쉐이프가 있어…` 를 찾아보세요.

## `거리로 병합` 이 아무것도 안 합친다

`병합할 정점이 없습니다` 라면 위치가 같아도 **UV0가 다른** 경우입니다. 이건 의도된 동작으로, UV 심을 지키기 위한 규칙입니다. → [편집](/guides/edit#거리로-병합)

블렌드쉐이프 델타가 서로 크게 다른 정점도 같은 이유로 병합에서 빠집니다.

## 스크립트를 저장했더니 창이 초기화됐다

세션은 자동으로 복원됩니다. 콘솔에서 확인하세요.

- `Easy Mesh Editor: 자동 저장된 편집 세션을 복원했습니다 ({0})`
- `Easy Mesh Editor: 자동 저장본 {0}개를 복원하지 못했습니다. 파일은 그대로 두었습니다: {1}`

창을 두 개 열어 두었다면 하나만 복원됩니다. → [자동 저장과 복원](/internals/session-and-undo#자동-저장과-복원)

## `Bake` 했는데 다른 파일이 생겼다

같은 원본을 쓰는 렌더러가 여럿이고 씬이 저장되지 않은 상태였을 수 있습니다.

> `씬이 저장되지 않아 렌더러를 식별할 수 없습니다.`

씬을 저장한 뒤 다시 `Bake` 하세요. → [provenance와 owner](/reference/output-files#provenance와-owner)

이름이 같은 다른 에셋이 이미 있었다면, 그것을 덮어쓰지 않으려고 일부러 새 경로를 만든 것입니다.

## `Ctrl+Z`를 눌렀더니 편집이 취소됐다

블렌드쉐이프 트랜잭션 중에 되돌리기가 편집 시작 시점보다 앞으로 간 경우입니다.

> `실행취소가 '{0}' 편집 시작 이전까지 되돌아가 편집 내용이 무효화되었습니다. 안전을 위해 편집을 취소했습니다.`

기준이 사라져 그대로 진행하면 잘못된 델타가 저장되므로, 조용히 계속하지 않고 취소합니다.

## 컴파일 오류가 난다

DLL판과 소스판을 겹쳐 넣었을 가능성이 큽니다. 같은 클래스가 두 번 정의됩니다. 둘 중 하나만 남기세요. → [설치](/getting-started/installation)
