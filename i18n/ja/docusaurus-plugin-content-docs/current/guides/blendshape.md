# ブレンドシェイプ

**このドキュメントを読むと**、表情キー一覧の処理方法、新しいキーの造形と既存キーを再編集するトランザクション、ミラーキー・転送・結合などの管理機能、および`新規キーとして保存`と`Bake`の違いが理解できます。

:::note[`SkinnedMeshRenderer`専用です]
通常の`MeshRenderer`ターゲットでは、`ブレンドシェイプはSkinnedMeshRenderer専用です。通常のMeshRendererでは使用できません。`が代わりに表示されます。
:::

## リスト {#목록}

ヘッダーは`ブレンドシェイプ {0}個`です。各行に名前、値スライダー、数値入力があります。

- 値は`0～100`で、リアルタイムでプレビューに反映されます。
- 名前または値を左右にドラッグしても値が変わります。`Shift`を一緒に押すと微調整です。
- `全て0にリセット`で一度にリセットします。

リストの上の検索ボックスで名前をフィルタリングします。`×`で検索をクリアします。

表示するキーがない場合は、`表示するブレンドシェイプがありません。「+ 新規シェイプ」で作成してください。`が表示されます。

### 行の3つのボタン

| ボタン | 動作 |
|---|---|
| `S` | そのキーのみを100で表示するソロプレビュー（`Esc`で解除） |
| `L` | 誤操作防止ロック |
| `M` | ミラーキーを作成 |

### プリフィックスグループ {#접두사-그룹}

`グループ`を有効にすると、名前のプリフィックスでリストが折り畳まれます。`_`を主な区切り文字として見ます — `eye_blink`、`eye_wide`は`eye`グループにグループ化されます。グループヘッダーは`{名前} ({数})`形式です。

### 拡張範囲 {#확장-범위}

`拡張範囲`を有効にするとスライダーが`-100～200`まで開きます。外挿なので形状が崩れる可能性があります — プレビュー用に使用し、そのまま保存しないでください。

### デルタヒートマップ {#델타-히트맵}

`ヒートマップ`を有効にしてリストでキー名をクリックすると、そのキーが実際に移動する頂点が色で表示されます。状態は`ヒートマップ: 「{0}」・最大移動量 {1}`で表示されます。

キーを選択していない場合は、`ヒートマップを表示するにはリストでキー名をクリックして選択してください。`が表示されます。

### ソロプレビュー {#솔로-프리뷰}

行の`S`をクリックすると、そのキーのみが100で有効な状態が表示されます。他のキーの値は画面から一時的に削除されます。`Esc`で解除します。

ソロ中は複数キーの値を一度に変更できません — `ソロプレビュー中はウェイトを一括変更できません。先にソロ（ピン）を解除してください。`

### ロック {#잠금}

行の`L`でそのキーをロックします。ロック中のキーを編集しようとすると、`キー「{0}」はロックされています。行の「L」をもう一度押してロックを解除してください。`が表示されます。ロックは一括操作とキー転送でも尊重されます。

## 複数キーを一度に {#다중-선택}

名前をクリックで選択、`Ctrl`・`Shift`クリックで複数を選択します。`Shift`範囲選択は画面に表示される行を基準にしています。選択数は`選択 {0}個`で表示されます。

| ボタン | 動作 |
|---|---|
| `値を適用` | 選択したキーすべてに同じ値を設定 |
| `0にする` | 選択したキーを0に |
| `ロック` / `解除` | 選択したキーをロック/解除 |
| `^` / `v` | 順序を上下に移動 |
| `削除` | 選択したキーを削除 |
| `選択解除` | 選択のみを解除 |

削除は`選択したキー {0}個を削除しますか？Ctrl+Z一回で全て戻せます。`で確認されます。一括構造変更は1つの元に戻すステップです。

選択したキーがすべてロックされている場合は、`選択したキーが全てロックされているため、何も変更しませんでした。`で終了します。途中で失敗した場合は、`一括処理に失敗したため、全メッシュを実行前の状態へ戻しました。`ですべてロールバックされます。

## 新規シェイプを造形 {#새-쉐이프-조형}

`+ 新規シェイプ（N）`またはシーンビューで`N`。

現在の絶対的な形態に基づいて造形が開始され、シーンビューに`新規シェイプ造形中: {0}`バナーが表示されます。

- ドラッグ = グラブ、`Shift` = スムーズ
- `F` = 半径、`Shift+F` = 強度
- `Enter` = `新規キーを確定（Enter）`、`Esc` = `キャンセル（Esc）`

名前は`名前`フィールドで決定します。使用できない文字がある場合は、`キー名に使用できない文字（/ \ 改行 タブ）を「_」に置き換えて「{0}」として保存しました。`と一緒にクリーンアップされます。

## 既存キーを編集 {#기존-키-편집}

行の編集ボタンをクリックすると、そのキーの**最後のフレーム100%形態**が単独プレビューとして読み込まれ、編集トランザクションが開始されます。ウィンドウバッジが`編集確定待ち`になり、シーンビューに`編集中のシェイプ: {0}`バーが固定されます。

トランザクション中でも`スカルプト`・`編集`タブに移動して作業できます（`マルチタブ編集`）。ウィンドウはこのようにガイドします — `スカルプト/編集タブで修正後、ここへ戻って保存します。頂点数が変わる操作は保存できません。`

終了する際には、固定バーから以下のいずれかを選択します。

- `現在のキーを確定（Enter）` — セッションに確定します。
- `キャンセル（Esc）` — 破棄します。

:::caution[ここで確定してもまだアセットは変わりません]
ウィンドウの説明そのもの — `ここではシェイプ変更を作業セッションへ確定します。すべての作業完了後、上部のBakeでメッシュアセットへ最終保存します。`
:::

確定せずに保存を押すと、`シェイプ「{0}」は編集中です。現在のキー変更を確定またはキャンセルしてから最終保存してください。`と一緒にブレンドシェイプタブに戻ります。

### 複数フレームキー {#다중-프레임}

複数フレームのキーを編集する場合、警告が表示されます — `このキーは {0}フレームあります。最後の（100%）フレームのみ編集されます`

保存すると、`中間フレーム {0}個は最後のフレームの変化量に比例して更新されました。`で報告されます。中間フレームを個別に編集する機能はありません。→ [制限事項](/limitations)

### 元に戻すが編集開始前まで進む場合

`Ctrl+Z`が編集開始時点より前まで進んでしまう場合、トランザクションが成立しません。この場合、ツールは編集を自動的にキャンセルして通知します — `取り消しが「{0}」編集開始前まで戻り、編集内容が無効になりました。安全のため編集をキャンセルしました。`やり直しにも同じルールが適用されます。

## ベースメッシュを直接編集 {#기본형-직접-수정}

キーを選択せずに`スカルプト`または`編集`でメッシュを変更するとベース編集になります。ブレンドシェイプタブが`基本形の直接編集を検出 — 新規キーとして保存してください`と通知し、2つのボタンを表示します。

- `新規キーとして確定` — その変形を新しいキーにします。
- `基本形の編集を元に戻す` — `キー未選択で行った編集をすべて元に戻しますか？`

この状態で`Bake`を押すと、ウィンドウは`基本形に焼き込む`と新規キー確定のどちらかを質問します。

## 管理 {#관리}

| ボタン | 動作 |
|---|---|
| `名前` | 名前を変更します |
| `複製` | 同じ内容のキーをもう1つ作成します（`_Copy`） |
| `リバート` | 反転キーを作成します（`_Revert`）。ベースメッシュが変更されたアバターで元の表情を復元するときに使用します |
| `削除` | `シェイプ「{0}」を削除しますか？Ctrl+Zで戻せます。` |
| `^` / `v` | 順序を移動します |

同じ名前のキーが複数ある場合は、`このメッシュに同じ名前のキーが複数あります（例：「{0}」）。リストでクリックした項目のみが編集されます。`と通知されます。

### 適用値を結合 {#적용값-합치기}

`適用値を結合`は、現在0以外のキーの**表示結果**を1つの新しい100%キーに結合し、素材として使用された元のキーの値を0にリセットします。複数フレームキーの補間・外挿まで計算します。

### ミラーキー {#미러-키}

行の`M`または`ミラー軸`を設定して実行します。結果は`ミラーキー「{0}」を{1}軸基準で作成しました。`です。

名前は元の名前の左右表記を反転して決定されます。ルールは順序として:

| 元の名前 | ミラー名 |
|---|---|
| `...Left...` | `...Right...`（大文字小文字を区別しない照合も試行） |
| `xxx_L` | `xxx_R` |
| `L_xxx` | `R_xxx` |
| `xxx.L` | `xxx.R` |
| 左右表記なし | `xxx_Mirror` |

頂点ペアリングは`スカルプト`・`編集`対称と同じ空間マッチングを使用します。ペアなし頂点は対称平面上にあるときのみ反射され、そうでなければ動きません。法線デルタも同じ反射を受け、複数フレームの場合はすべてのフレームがミラーされます。

ペアが見つからない場合は、`「{0}」のミラーキーを作成できませんでした。対称の対応が見つからないか、メッシュが無効です。`で終了します。

### 別のメッシュからキーを取得 {#키-전송}

`別メッシュからキーを取り込む`セクションです。アバター顔の表情キーを新しく作成したヘアーやアクセサリーに移すときに使用します。

1. `ソースメッシュ`を指定します — `ソースメッシュを指定するとそのメッシュのキー一覧が表示されます。`
2. 転送するキーをチェックします。`全選択` / `全解除`があります。
3. `最大距離`を決定します。この距離内で対応点を見つけます。
4. `転送`をクリックします。

結果は`キー {0}個を取り込みました。対応点が見つからなかった頂点 {1}個は動きません — 最大距離を大きくしてみてください。`で表示されます。

| 状況 | メッセージ |
|---|---|
| 編集中のメッシュをソースに指定 | `編集中のメッシュはソースにできません。別のメッシュを指定してください。` |
| ソースがRead/Write無効 | `ソースメッシュのRead/Writeが無効なため頂点を読めません。` |
| ソースにキーなし | `このソースメッシュにはブレンドシェイプがありません。` |
| 同じ名前がすでに存在 | `同じ名前のキーが {0}個あります。取り込んだ内容で置き換えますか？` |
| ロック中のキーが混在 | `ロック中のキー {0}個をスキップしました。` |

失敗した場合は、`取り込みに失敗したため、全メッシュを実行前の状態へ戻しました。`ですべてロールバックされます。

## クイックキャプチャとBake {#빠른-캡처와-bake}

両方とも保存ですが、動作が異なります。

| | `新規キーとして保存` | `Bake` |
|---|---|---|
| 保存対象 | ベースへ追加した変形**のみ**を新しいキーとして | Work Mesh**全体**（頂点・ウェイト・キー構造） |
| アセット | 変更されない | `<元名>_Edit.asset`を作成 |
| セッション | 継続 | 終了 |
| ベース | 保持 | 現在の状態のまま |

`新規キーとして保存`はブレンドシェイプ値で再生中の形状を混ぜません。保存されたキーは100で有効になり、現在の外観が保持され、次のキャプチャ基準が更新されて、以前の変形は2回保存されません。

ウィンドウのガイドそのもの — `基本形は保持されます。新規キーは100で有効になり、現在の外観が保持され、次のキャプチャには今回のキーは含まれません。`

キャプチャする変形がない場合は、`新規キーへ取得する追加ベース変形がありません。`が表示されます。

## 複数メッシュで {#다중-메쉬-키}

すべてのターゲットが`SkinnedMeshRenderer`である必要があります — そうでなければ`複数メッシュのブレンドシェイプを同時編集するには、選択対象がすべてSkinnedMeshRendererである必要があります。`

リストには**すべてのターゲットで名前が同じキーのみ**が表示されます（`共通ブレンドシェイプ {0}個・メッシュ {1}個`）。インデックスは異なる場合があります。値・編集・管理はすべてのメッシュに同時に適用されます。

共通キーがない場合は、`選択した全メッシュに共通するブレンドシェイプがありません。新規キーは同じ名前で全てに追加されます。`が表示されます。→ [マルチメッシュ](/guides/multi-mesh)
