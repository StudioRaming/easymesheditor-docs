# 複数メッシュ

**このページを読むと** 1 つのセッションで複数のメッシュを一緒に扱うとき、どの操作がすべてのメッシュに適用され、どの操作がアクティブ対象だけに適用されるか、共通ギズモの動作、1 つの操作が失敗したときの扱いがわかります。

## まとめて読み込む

Hierarchy で複数のオブジェクトを選び、`読み込み` を押します。すべてが同じセッションに読み込まれます。

同じ元のメッシュを使うレンダラーも、**それぞれ別々に**読み込み、別々に編集します。除外されることはありません。各レンダラーの結果は個別に保存され、ファイルが互いに上書きしないよう、レンダラーごとに出力が分けられます。→ [生成されるファイル](/reference/output-files#provenance와-owner)

メッシュごとにトポロジーや頂点数が異なっていても構いません。各メッシュは自分のデータで個別に計算されます。

## アクティブ対象 {#활성-대상}

`アクティブ対象` のセレクターで、フォーカスされているメッシュを切り替えます。すべてのメッシュに適用される操作と、アクティブ対象だけに適用される操作があります。

| タブ | 範囲 |
|---|---|
| `形を整える` | 読み込んだすべてのメッシュ |
| `選択・移動` | すべてのメッシュで選択を保ち、共通ギズモでまとめて変形 |
| `表情キー` | 同じ名前のキーだけが、すべてのメッシュに同時に適用される |
| `ボーン接続` | アクティブ対象のみ |

削除と分離は、アクティブなメッシュだけに適用されます。

## 選択・移動タブの共通ギズモ

複数のメッシュでそれぞれ要素を選ぶと、**ワールド空間の共通ギズモ 1 つで**、すべてのメッシュをまとめて変形します。

- `G` / `R` / `S` の[モーダル変形](/guides/edit#모달-변형)は、ワールド軸で動作します。複数のメッシュには、1 つにまとめられるローカル軸がないためです。
- `A`（すべて選択）、`Alt+A`（解除）、`Ctrl+I`（反転）は、すべての対象に適用されます。

[ピボット](/guides/edit#피벗)で `メッシュごとに均等` をオンにすると、共通ピボットを頂点数ではなくメッシュごとに同じ比重で計算します。

対称の対応点、選択、ブラシの影響は、常に各メッシュで個別に計算されます。

## 表情キーの名前の積集合 {#표정-키}

複数のメッシュにまたがって表情キーを編集するには、すべての対象が `SkinnedMeshRenderer` である必要があります。一覧に表示されるのは、**すべての対象で名前が同じキーだけ**です。

インデックスは異なっていても構いません。名前だけで対応付けます。値、編集、管理は、すべてのメッシュに同時に適用されます。共通のキーがない場合は一覧が空になり、新しく作るキーは同じ名前ですべてのメッシュに追加されます。→ [表情キー](/guides/blendshape#다중-메쉬-키)

## アトミックなロールバック {#원자적-롤백}

複数のメッシュの構造を変える操作（一括削除、順序の変更、キーの取り込み、分離など）は、**すべて成功するか、すべて元に戻る**かのどちらかです。1 つでも失敗すると、すべての対象を操作の前の状態に戻します。

元に戻す操作も同じです。複数メッシュの操作は、1 つの元に戻す段階としてまとめられます。→ [セッションと元に戻す](/internals/session-and-undo)

## メッシュ保存はメッシュごとに行われます

`メッシュ保存` は、対象ごとに別々の `<元の名前>_Edit.asset` を作ります。ロールバックの規則とは異なり、ここでは成功した対象だけが書き出され、失敗した対象のセッションは開いたままになります。

結果は、対象ごとの成功・失敗を示す折りたたみ式の表として表示されます。→ [ウィンドウの使い方](/guides/window#저장-결과표)

## パフォーマンス

高密度のメッシュを複数開くと、シーンビューのオーバーレイ、ボックスピッキング、スキンのポーズ計算、ブラシ処理のコストがその分増えます。重く感じる場合は、必要なメッシュだけを読み込んでください。読み込み候補の一覧から、行ごとに読み込めます。→ [ウィンドウの使い方](/guides/window#불러올-후보)
