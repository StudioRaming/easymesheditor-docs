# トラブルシューティング

症状で探してください。ほとんどは**「セッションが開かなかった、またはターゲットタブではない、またはトランザクションが開いている」**のいずれかです。

## ウィンドウは開くが何もできない

| 確認 | 対処 |
|---|---|
| ターゲット行が`ターゲットなし — オブジェクトを選択してLoad` | Hierarchyからメッシュレンダラーがあるオブジェクトを選んでください |
| `選択: {0}個レンダラー（Loadを押してください）`で止まっている | `Load`をまだ押していません |
| `編集が一時的に無効です。` | `Tab`または`編集を有効化`を押してください |
| タブ本体ではなくガイドテキストだけ表示 | そのタブは`SkinnedMeshRenderer`専用です |

## `Load`が働かない

| 原因 | メッセージ/表示 | 対処 |
|---|---|---|
| メッシュレンダラーがない | `選択したオブジェクトで編集可能なメッシュレンダラーが見つかりません。` | 子を含めてレンダラーがあるか確認 |
| Read/Writeがオフ | `メッシュがRead/Write無効です。`· 候補行に`[Read/Write無効]` | ウィンドウの`Read/Write有効化`ボタン |
| 同じソースを共有するレンダラー | 候補行に`[ソース重複]` | 自動的に1つだけ開きます |

## `ブレンドシェイプ` / `ウェイト`タブが無効

この2つのタブは`SkinnedMeshRenderer`専用です。

- `ブレンドシェイプはSkinnedMeshRenderer専用です。通常のMeshRenderer対象では使用できません。`
- `ウェイトペイントはSkinnedMeshRenderer専用です。`

複数のメッシュを一緒に開いた場合、**すべて**SMRである必要があります — `複数のメッシュのブレンドシェイプを一緒に編集するには、選択したターゲットがすべてSkinnedMeshRendererである必要があります。`

## `Bake`ボタンが押せない

バッジが`トランザクション中`かどうか確認してください。ブレンドシェイプ編集が確定されていないと`新規シェイプとして保存`と`Bake`の両方がブロックされます。

> `'{0}'シェイプはまだ編集中です。現在のキー変更を確定またはキャンセルしてから最終保存してください。`

シーンビューの固定バーで`Enter`（確定）または`Esc`（キャンセル）をまず実行してください。→ [ブレンドシェイプ](/guides/blendshape#기존-키-편집)

## シーンビューに何も描画されない

| 原因 | 対処 |
|---|---|
| **2つのシェーダーが見つかりません** | `Editor/Shaders/EmeOverlay.shader`と`EmeSceneGL.shader`を一緒にインストール → [インストール](/getting-started/installation) |
| 編集がオフ | `Tab` |
| 隠れた要素を表示しようとしている | `Alt+Z`でX-Rayオン |

## `Alt+クリック`がエッジループの代わりにカメラを回す

意図的な動作です。ループ選択は**ドラッグしないクリック**でのみ発生します。マウスをほぼ動かさずに放してください。→ [編集](/guides/edit#엣지-루프와-엣지-링)

## `R`が回転モーダルではなくスケールギズモになる

`R`は選択があり、カーソルがシーンビューの上にあるときだけ回転モーダルです。選択がないか、カーソルがウィンドウ側にあるとUnity式`R`=スケールギズモとして動作します。

## シーンビューで`X` `Y` `Z`を押しても対称がオンにならない

`スカルプト`と`編集`の両方で軸対称ショートカットは`Shift+Alt+X` / `Y` / `Z`です。単独キーはUnityのツールハンドルショートカットのために予約しています。ウィンドウの`対称`チェックボックスでもオンにできます。→ [ショートカット](/reference/shortcuts)

## 対称が反対側に効かない

| 原因 | 対処 |
|---|---|
| 軸を間違えた | `対称平面を表示`をオンにして平面位置を確認 |
| 非対称な編集をした後 | 対称マップはストローク開始ごとに検査して更新されます。もう一度試してください |
| 元々左右非対称のメッシュ | ペアが見つからない頂点は単にスキップされます |

## ウェイトをペイントしても何も起こらない

| 原因 | メッセージ | 対処 |
|---|---|---|
| アクティブな本がない | `アクティブボーンがありません — リストの左ラジオで塗るボーンを選んでください。` | ラジオでボーンを選択 |
| ボーンがロックされている | `ターゲットボーンがロックされているため頂点{0}個をスキップします` | 行の`L`でロック解除 |
| スロットが満杯 | `4つのスロットがいっぱいの頂点{0}個をスキップします（弱い値）` | 他のボーンのウェイトを先に削除するか`最大影響ボーン数`を確認 |

## ウェイト転送の結果が全体的にずれている

ソースとターゲットの変換が異なる場合です。ウィンドウが警告を出したら`ソーストランスフォームを無視（バインドポーズのローカル空間で照合）`をオンにして再実行してください。→ [ウェイトペイント](/guides/weight-paint#전송-공간)

一部の頂点だけずれている場合は`最大距離`を少し上げてみてください。`範囲外{1}頂点`の数が減ります。

## キーを編集したら他のフレームが変になった

フレームが複数あるキーは最後のフレーム（100%）だけが編集され、中間フレームはその変化量に**比例して**更新されます。

> `このキーは{0}個のフレームです。最後のフレーム（100%）だけ編集されます`

中間フレームを個別に扱う機能はありません。→ [制限事項](/limitations)

## 削除したのにポリゴン数が減らない

未使用頂点整理は`Bake`するときに1回起こります。編集中はライブメッシュのインデックスを変更しないためです。→ [未使用頂点の整理](/internals/bake#고아-정점-정리)

`Bake`後も減らなかったらスキップされたということです。コンソールで`三角形以外のサブメッシュ…`または`同じ名前のブレンドシェイプがあるため…`を探してください。

## `距離でマージ`が何も結合しない

`マージする頂点がありません`なら位置が同じでも**UV0が異なる**場合です。これは意図的な動作で、UVシームを保持するためのルールです。→ [編集](/guides/edit#거리로-병합)

ブレンドシェイプデルタが大きく異なる頂点も同じ理由でマージからスキップされます。

## スクリプトを保存したらウィンドウが初期化された

セッションは自動的に復元されます。コンソールを確認してください。

- `Easy Mesh Editor: 自動保存した編集セッションを復元しました（{0}）`
- `Easy Mesh Editor: 自動保存 {0}件を復元できませんでした。ファイルは保持しています: {1}`

2つのウィンドウを開いていた場合は1つだけが復元されます。→ [自動保存と復元](/internals/session-and-undo#자동-저장과-복원)

## `Bake`したら別のファイルが生成された

同じソースを使うレンダラーが複数あり、シーンが保存されていない状態だった可能性があります。

> `シーンが保存されていないためレンダラーを特定できません。`

シーンを保存してから再度`Bake`してください。→ [provenance と owner](/reference/output-files#provenance와-owner)

同じ名前の別のアセットがすでに存在した場合は、それを上書きしないために意図的に新しいパスを作成したのです。

## `Ctrl+Z`を押したら編集がキャンセルされた

ブレンドシェイプトランザクション中に元に戻す動作が編集開始時点より前に戻った場合です。

> `実行取消が'{0}'編集開始前まで戻り、編集内容が無効になりました。安全のため編集をキャンセルしました。`

基準がなくなったため、そのまま続行すると不正なデルタが保存されるので、静かに続行せず、キャンセルします。

## コンパイルエラーが出る

DLL版とソース版を一緒に入れた可能性があります。同じクラスが2回定義されます。どちらか1つだけ残してください。→ [インストール](/getting-started/installation)

## それでも動かない場合

`studioraming@gmail.com`にUnityバージョン、レンダーパイプライン、製品バージョン、コンソールログ全文、再現手順を送ってください。
