# 現在の制限

Easy Mesh Editor `0.1.1`基準です。ここに書かれたものはバグではなく、**このバージョンでまだ実装していない機能**です。

## ない機能

| 機能 | 状態 |
|---|---|
| 押し出し（Extrude） | 未実装 |
| インセット（Inset） | 未実装 |
| ベベル（Bevel） | 未実装 |

3つとも新しいフェイスを生成するトポロジー編集のため、別の作業として分けました。このバージョンの`編集`タブは既存フェイスの選択、移動、削除、分離、マージまでです。→ [編集](/guides/edit)

## ターゲット制限

- `ブレンドシェイプ`と`ウェイト`タブは**`SkinnedMeshRenderer`専用**です。通常の`MeshRenderer`は`スカルプト`・`編集`・`Bake`までのみです。
- 複数メッシュを一緒に扱うときは`ブレンドシェイプ`のターゲットが**すべて**SMRである必要があります。
- 読み書きできないメッシュ、三角形以外のトポロジー、破損したメッシュデータは正常な編集を保証しません。

## ボーンウェイト

- 直接ペイント はUnityのレガシ**4スロット**範囲で動作します。
- Unity 2020.1以上で**ペイントしていない**頂点の5個以上の本の影響は保存されます。→ [可変ボーンウェイト](/internals/bake#가변-본-웨이트)
- Unity 2019.4シリーズには可変ボーンウェイトAPIそのものがありません。4スロットのみです。
- `選択を分離（P）`で取り出したパートは元が5個以上の影響を持っていても**4スロットに制限**されます。

## ブレンドシェイプ

- フレームが複数あるキーは**最後のフレーム（100%）だけ編集**されます。保存すると中間フレームがその変化量に比例して更新されます。中間フレームを個別に造形する方法はありません。
- 同じ名前のキーが複数ある場合は、リストでクリックした項目だけが編集されます。
- トランザクション中は頂点数が変わる作業（削除・分離）をキーとして保存できません。

## シーンビュー操作

- `Alt+クリック`エッジループは**ドラッグしないクリック**でのみ動作します。Unityの`Alt+ドラッグ`シーン回転を奪わないためのルールです。→ [編集](/guides/edit#엣지-루프와-엣지-링)
- 軸対称ショートカットは`Shift+Alt+X` / `Y` / `Z`です。単独の`X` `Y` `Z`と`Alt+Z`はそれぞれUnityツールハンドルとX-Rayのために予約しており、傍受しません。
- シーンビューショートカットはテキスト入力中は動作せず、Unityのグローバルショートカットプロファイルを変更しません。
- `ウェイト`タブの`対称ペイント（X）`ラベルに`（X）`が付いていますが、**ウィンドウのチェックボックスのみで**オンオフします。

## ウィンドウとドッキング

- ウィンドウの高さが足りなければ[コンパクトモード](/guides/window#컴팩트-모드)に自動切り替えされ、副題と`使用ガイド`ガイドブロックが隠れます。トグルで無効にできません。
- ウィンドウを**2つ以上**開いて スクリプトが再コンパイルされると、自動保存は1つだけ復元されます。
- 自動保存にdirty判定はありません。`Load`だけして何もしなくても保存・復元対象です。
- エディタークラッシュは自動保存の対象ではありません。

## パフォーマンス

- 高密度メッシュはシーンビューオーバーレイ、正確なボックスピッキング、スキンポーズ計算、ブラシ処理のコストが増えます。
- 複数のメッシュを一緒に開くとそのコストが加算されます。必要なものだけ選んでください。→ [マルチメッシュ](/guides/multi-mesh)
- 構造元に戻すスナップショットはメモリ上限があります。超過すると古い記録から削除されます。

## 実行環境

- **Unity Editor専用**です。プレイヤービルド用のランタイム機能ではありません。
- サポート範囲は**Unity 2019.4.31f1～2022.3.22f1**です。
- DLL版とソース版を同じプロジェクトに一緒に入れるとコンパイルエラーが出ます。

## 推奨事項

重要なプロジェクトはバージョン管理や別途バックアップを取ってください。`Bake`は元のメッシュを上書きしませんが、レンダラーが指すメッシュは変わります。
