# 現在の制限

Easy Mesh Editor `1.0.0` の時点の内容です。ここに書かれているものはバグではなく、**このバージョンではまだ行わない作業**です。

## 未対応の機能

| 機能 | 状態 |
|---|---|
| 押し出し（Extrude） | 未実装 |
| インセット（Inset） | 未実装 |
| ベベル（Bevel） | 未実装 |

3 つとも新しい面を作り出す位相編集なので、別の作業として扱っており、このバージョンには含まれません。このバージョンの `選択・移動` タブでできるのは、既存の面を選ぶ、動かす、削除する、分離する、結合するところまでです。位相編集は、削除、分離、距離でマージまでです。→ [選択・移動](/guides/edit)

## 対象の制限

- `表情キー` と `ボーン接続` のタブは、**`SkinnedMeshRenderer` 専用**です。通常の `MeshRenderer` で使えるのは、`形を整える`、`選択・移動`、`メッシュ保存` までです。
- 複数のメッシュをまとめて扱う場合、`表情キー` はすべての対象が SMR である必要があります。
- 読み書きできないメッシュ、三角形ではないトポロジー、壊れたメッシュデータは、正しく編集できることを保証しません。

## ボーンウェイト

- 直接塗る操作は、Unity の従来の **4 スロット**の範囲で動作します。
- **塗っていない**頂点の 5 つ以上のボーン影響は保持されます。→ [可変ボーンウェイト](/internals/bake#가변-본-웨이트)

## 表情キー

- 複数のフレームを持つキーは、**最後のフレーム（100%）だけが編集**されます。保存すると、途中のフレームは最後の変化量に比例して更新されます。途中のフレームを個別に造形する方法はありません。
- 同じ名前のキーが複数ある場合、一覧でクリックしたものだけが編集されます。
- 表情キーの編集中は、頂点数が変わる操作（削除、分離）を、キーとして保存できません。

## シーンビューでの操作

- `Alt+クリック` のエッジループは、**動かさなかったクリック**でのみ動作します。Unity の `Alt+ドラッグ` によるシーンの回転を奪わないための規則です。→ [選択・移動](/guides/edit#엣지-루프와-엣지-링)
- 軸の対称のショートカットは `Alt+Shift+X` / `Y` / `Z` です。単独の `X` `Y` `Z` と `Alt+Z` は、それぞれ Unity のツールハンドルと X-Ray として残しているため、このツールは横取りしません。
- シーンビューのショートカットは、テキスト入力中は動作せず、Unity のグローバルな Shortcut プロファイルも変更しません。
- `ボーン接続` タブの `対称ペイント（X）` は、ラベルに `(X)` が付いていますが、ウィンドウのチェックボックスでのみオン・オフします。

## ウィンドウと自動保持

- ウィンドウを **2 つ以上**開いたままスクリプトが再コンパイルされると、自動保持から復元されるのは 1 つだけです。
- 自動保持は、変更があったかどうかを判定しません。`読み込み` しただけで何もしていなくても、保持と復元の対象になります。
- エディターが予期せず終了した場合、自動保持は実行されません。代わりに、保存していない編集がある間は少なくとも 60 秒ごとにチェックポイントが保存され、次にウィンドウを開いたときに、復元バナーで復元を選べます。

## パフォーマンス

- 高密度のメッシュは、シーンビューのオーバーレイ、正確なボックスピッキング、スキンのポーズ計算、ブラシ処理のコストを、その分増やします。
- 複数のメッシュを一緒に開くと、そのコストが加算されます。必要なものだけを開いてください。→ [複数メッシュ](/guides/multi-mesh)
- 構造の元に戻すスナップショットには、メモリの上限があります。上限を超えると、古いものから破棄されます。

## 実行環境

- **Unity Editor 専用**です。プレイヤービルド用のランタイム機能ではありません。
- 対応範囲は **Unity 2019.4 ~ Unity 6（6000.0、6000.3 LTS）**、Built-in RP と URP です。
- DLL 版とソース版を同じプロジェクトに入れると、コンパイルエラーになります。
- 元のメッシュが `Assets` フォルダーの外にある場合（Unity の組み込みメッシュ、パッケージのメッシュ）は読み取り専用で、`メッシュ保存` では保存できません。`読み込み` の時点から案内します。1.0 は自動ではコピーしないため、メッシュを `Assets` フォルダーへコピーしてレンダラーに割り当て、読み込み直してください。

## 推奨事項

重要なプロジェクトでは、バージョン管理や別のバックアップを用意してください。`メッシュ保存` は元のアセットを上書きしませんが、レンダラーが参照するメッシュは変わります。
