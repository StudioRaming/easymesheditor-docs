# Bake の内部動作

**このドキュメントを読むと**、`Bake`がどの順序で何をするのか、いつ未使用頂点を整理し、いつスキップするのか、そして5個以上の本の影響を持つメッシュがどのように保存されるのかが理解できます。

## 処理順序

1. トランザクションが開いていれば中止します。
2. 自動正規化がオフの状態で作業していたらウェイトを1回正規化します。
3. Work Meshのコピーを作ります（ライブメッシュは変更しません）。
4. コピーから[未使用頂点を整理](#고아-정점-정리)します。
5. データを検証します — NaN/Infinity、トポロジー、配列長。
6. `provenance`で出力パスを決め、アセットを書き込みます。
7. レンダラーが新しいアセットを使うようにし、セッションを終了します。

メッシュが大きければ進捗バーが表示されます — `メッシュをベイク中` · `未使用頂点を整理中...` · `メッシュアセットを保存中...`

## 未使用頂点の整理 {#고아-정점-정리}

`選択を削除（X · {0}個のフェイス）`は三角形だけを削除し、頂点バッファはそのままにします。ライブWork Meshのインデックスが選択・マスク・元に戻すスナップショットと結合しているため、編集中に頂点を詰めなおすとそのすべてがずれるからです。

したがって整理は**`Bake`するときコピーで正確に1回**行われます。どのサブメッシュ三角形も参照されない頂点を削除し、残りをリマップします。

結果は`未使用頂点 {0}個を整理しました`と報告されます。

保持されるもの：法線・接線・UV0～UV7・カラー・ボーンウェイト（可変影響を含む）・bindpose・全ブレンドシェイプフレーム。

整理はステージングコピーで全プロセスを実行し、完全に成功したときだけターゲットにコピーされます。半分だけ上書きされたメッシュは残りません。

### スキップされる場合

| 条件 | メッセージ |
|---|---|
| 三角形ではないサブメッシュ（Quad/Line/Point）がある | `三角形以外のサブメッシュ(Quad/Line/Point)があるため未使用頂点の整理をスキップします。` |
| 同じ名前のブレンドシェイプがある | `同じ名前のブレンドシェイプがあるため未使用頂点の整理をスキップします。` |
| 整理自体が失敗した | `未使用頂点の整理に失敗したためメッシュはそのままです。` |

スキップしても`Bake`は続行します。頂点が減るだけです。

## 法線

`Bake`は法線を任意に再計算しません。編集中に明示的に作成されたものだけを反映します。

- `法線を再計算`— 選択頂点の法線を面積加重スムースで再計算します。
- `法線を反転`— 選択フェイスの巻き方向を反転し、ブレンドシェイプの法線・接線デルタと頂点接線も一緒に反転します。
- ブレンドシェイプキーを作成または修正するときは、そのキーの法線デルタが面積加重で再計算されます。既存キー保存、新規キー保存、`新規シェイプとして保存`の3つのパスすべて同じです。

## 可変ボーンウェイト {#가변-본-웨이트}

Unity 2020.1以降、メッシュは頂点あたり4個を超える本の影響を持つことができます。レガシ`BoneWeight`APIは4個までしか扱わないので、それだけを使うと**編集していない頂点までメッシュ全体が4スロットに切り詰められます。**

そこでセッションは`Load`時に元のデータの可変ウェイト情報を別に保存します。

- ウェイトをペイントすると、**タッチしたウェルドグループだけ**4スロットに置き換え、
- 残りは保存した元のデータのままにし、
- 保存するときに両方を合わせて一度に書き込みます。

結果として腕1本だけウェイトをペイントしても、脚の5影響頂点はそのまま残ります。

元に戻すスナップショット、削除・分離、最終同期まで、すべてこの経路を通ります。Unity 2019.4ではそもそも可変ウェイトがないため、レガシ4スロットのままです。

:::caution[分離されたパートは例外です]
`選択を分離（P）`で取り出した`_Part.asset`は4スロットに制限されます。→ [制限事項](/limitations)
:::

## 名前の合わせ

Unityはアセットファイル内のメインオブジェクト名がファイル名と異なると警告を出します。`Bake`は保存直前にメッシュオブジェクトの名前をファイル名と同じに合わせます。

## 失敗したとき

`Bake`が失敗すると**セッションは閉じられません。**

> `Bake失敗（成功 {0}/ 失敗 {1}）: {2}— 失敗したセッションは保持されるため再試行できます。`

複数のメッシュを一緒にベイクした場合、成功したものだけアセットになり、失敗したセッションは開いたまま再試行できます。結果は`Bake結果（{0}/{1}成功）`テーブルにまとめられます。→ [ウィンドウ使用法](/guides/window)

## カラーバッファ

メッシュのカラーチャネルが8ビット（UNorm8）でインポートされている場合、floatカラーをそのまま使うことはできません。スナップショット・整理・分離・セッション同期はすべて1つの読み書きパスを通り、元のメッシュの形式をそのまま使って書き込みます。
