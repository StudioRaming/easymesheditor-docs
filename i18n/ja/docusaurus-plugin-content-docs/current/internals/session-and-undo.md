# セッションと元に戻す

**このドキュメントを読むと**、`Load`が実際に何を変更するか、元に戻すがなぜストローク単位できっちり分かれるのか、トランザクションが何であり、なぜ`Bake`をブロックするのか、そしてスクリプトコンパイルで作業が生き残る理由が理解できます。

## Work Mesh {#work-mesh}

`Load`をクリックするとツールは元のメッシュを**複製**して一時メッシュを作成し、レンダラーのメッシュ参照をそのコピーに変更します。このコピーがWork Meshです。

- 元のアセットファイルは開くことも書き込むこともしません。
- すべての編集 — ブラシ、ギズモ、ウェイト、ブレンドシェイプ構造変更 — はWork Mesh上で行われます。
- セッションが終了すると（`Revert`、ウィンドウ を閉じる、プレイモード進入）レンダラーは元の参照に戻り、Work Meshは破棄されます。

`Bake`のみがこのコピーをファイルにエクスポートします。→ [Bake内部](/internals/bake)

## ウェルドグループ {#웰드-그룹}

Unityメッシュは、UVシーム、法線シーム、マテリアル境界で**同じ位置の頂点を複数に分割**します。画面では1つの点に見えますが、データには数個あります。

ツールはローカル空間位置が同じ頂点を1つの**ウェルドグループ**として扱います。

- 選択はグループ全体をキャッチします。
- ブラシとギズモ変形はグループ全体に同じ値を書き込みます。
- ウェイトペイント結果もグループ全体に同一に記録されます。

このため「1つの頂点だけ移動したのにUVシームが開きませんでした」が成立します。

対称も同じ概念の上にあります。左右対応はインデックスではなく、ローカル空間のベース位置のグループマッチングで見つけます — そのため左右の頂点数が正確に同じでなくても動作します。

## 元に戻す {#되돌리기}

Unityの`Ctrl+Z`をそのまま使用します。ツールは独自の元に戻すスタックを持たず、Unityのものを使用します。

**1つの意図 = 元に戻す1ステップ**がルールです。

| 作業 | 元に戻すユニット |
|---|---|
| ブラシストローク | マウスを押してから離すまで全体が1ステップ |
| ギズモ変形 | 1回のドラッグが1ステップ |
| `G`/`R`/`S`モーダル | 1回の確定が1ステップ |
| ウェイトブラシ | 1ストロークが1ステップ |
| `選択ボーンのスムーズ`スライダー | マウスを離すときに1ステップとして確定 |
| 削除・分離・マージ・キー構造変更 | 1つの作業が1ステップ |
| マルチメッシュ一括作業 | 全体が1つの複合ステップ |

マスク変更も元に戻す対象です。反対に**隠すはそうではありません** — メッシュデータではなくセッションの表示状態だからです（Blenderと同じルール）。

### 構造スナップショット

頂点数またはインデックスが変わる作業（削除、分離、マージ、キー追加・削除）は、1つの値を元に戻すことでは復旧できません。このような作業は**作業前にメッシュ全体をスナップショット**として保存し、元に戻すが来たときにそれを復元します。

スナップショットに含まれるもの：頂点・法線・接線・UV0～UV7・カラー・三角形とサブメッシュトポロジー・bindpose・ボーンウェイト（可変含）・全ブレンドシェイプフレーム。

スナップショットはメモリを消費するため上限があります。超えると古いものから削除され、通知されます — `構造変更のUndo履歴がメモリ上限を超えたため、古い記録{0}件を破棄しました。`

## トランザクション {#트랜잭션}

ブレンドシェイプの**新規キー造形**と**既存キー編集**は複数ステップにわたる作業であり、中間状態をそのまま保存してはいけません。そのため開始と終了が明示的なトランザクションでラップされます。

- 開始するとウィンドウバッジが`編集確定待ち`になり、シーンビューに固定バーが表示されます。
- `Enter` = 確定、`Esc` = キャンセル。ウィンドウにフォーカスがあっても同じキーが動作します。
- トランザクションが開いている間、`新規キーとして保存`と`Bake`の両方がブロックされます。

トランザクション中でも`スカルプト`・`編集`タブに移動して作業できます。ただし頂点数が変わる作業はキーとして保存できません — `頂点数が変わりました。構造編集を元に戻してから保存してください。`

### 元に戻すがトランザクションを無効にするとき

`Ctrl+Z`がトランザクション開始時点より前に戻ると、編集の基準が失われます。この場合、ツールは黙って進行せず、編集をキャンセルします。

> `取り消しが「{0}」編集開始前まで戻り、編集内容が無効になりました。安全のため編集をキャンセルしました。`

やり直しも同じです。判定は観測ではなく、トランザクション開始時に記録された値に基づいているため、決定論的です。

## 自動保存と復元 {#자동-저장과-복원}

Unityはスクリプトを保存するたびドメインを再ロードします。その際、エディターウィンドウの状態のほとんどが初期化されます。編集セッションをそのままにしておくと、保存していない作業が警告なしに消滅します。

そのため、リロード直前に以下を行います。

1. 進行中のトランザクションを静かに確定します（モーダルダイアログは表示しません — リロード中は表示できません）。確定できないとキャンセルします。
2. Work Meshを`Library/EmeAutoSave/<レンダラー ID>.asset`に直列化します。
3. リロード終了後、自動的に再読み込みしてセッションを復元します — `Easy Mesh Editor: 自動保存した編集セッションを復元しました（{0}）`

既知の制限事項：

- dirty判定がありません。`Load`だけして何もしなくても保存・復元します。
- ウィンドウを2つ開いていた場合、1つだけが復元されます。
- エディタークラッシュは対象ではありません。

ウィンドウを閉じたり、プレイモードに入るときは自動保存ではなく、質問されます — `Bake` / `破棄`（プレイモードは`キャンセル`も含む）。→ [生成されるファイル](/reference/output-files#자동-저장-폴더)

## セッションが終了する方法

| 方法 | 結果 |
|---|---|
| `Bake` | アセットとして保存して終了 |
| `Revert` | 元に戻して終了 |
| ウィンドウを閉じる | 質問後に終了 |
| プレイモード進入 | 質問後に終了 |
| 別のターゲットに切り替え | `「{0}」の編集内容はまだ保存されていません。... 編集を破棄して対象を切り替えますか？` |

`Tab`はここにはありません。編集入力だけを無効にし、セッションは生き残ります。

セッション中にレンダラーまたはメッシュがシーンから消えた場合、そのセッションだけが静かにクリーンアップされ、残りは保持されます。
